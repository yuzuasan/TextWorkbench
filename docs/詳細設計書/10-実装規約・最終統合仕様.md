# TextWorkbench 詳細設計書 第10部：実装規約・最終統合仕様

## 1. 本書の目的

本部は、第1部～第9部で確定した詳細設計を実装へ落とし込む際の共通規約と、コンポーネント間の最終的な接続仕様を定義する。

本部に記載された内容は、個別部の設計と矛盾しない範囲で、実装時の判断基準として扱う。

---

## 2. ソリューション構成

ソリューションは以下の構成とする。

```text
TextWorkbench.sln
├─ TextWorkbench
│  ├─ Presentation
│  │  ├─ Views
│  │  ├─ ViewModels
│  │  ├─ Behaviors
│  │  └─ Services
│  ├─ Application
│  │  ├─ Services
│  │  ├─ Interfaces
│  │  └─ UseCases
│  ├─ Domain
│  │  ├─ Models
│  │  └─ Enums
│  └─ Infrastructure
│     ├─ File
│     ├─ Encoding
│     ├─ LineEnding
│     └─ Diff
└─ TextWorkbench.Tests
```

### 2.1 レイヤー依存

基本的な依存方向は以下とする。

```text
Presentation
    ↓
Application
    ↓
Domain

Infrastructure → Application / Domain
```

Infrastructure の具体実装は Composition Root で Application のインターフェースへ接続する。

Presentation から Infrastructure の具体クラスを直接利用しない。

---

## 3. Composition Root

Composition Root は `App` とする。

`App` で以下を手動生成して接続する。

1. Infrastructure のサービス
2. Application のサービス
3. Presentation のダイアログ・通知サービス
4. UseCase
5. Workspace
6. MainWindowViewModel
7. MainWindow

MVPではDIコンテナを使用しない。

また、Shift-JIS利用のための `CodePagesEncodingProvider` 登録はアプリ起動時に1回だけ行う。

Composition Root以外でサービス実装を直接生成することは避ける。

---

## 4. 実装時の状態管理原則

### 4.1 Document

DocumentはWPFやAvalonEditを知らない純粋なデータモデルとする。

主な状態：

```text
Id
FilePath
FileName
CurrentContent
Encoding
LineEnding
IsModified
IsReadOnly
IsLoading
IsSaving
```

内部テキストの改行コードは常にLFとする。

ファイル読み込み時にLFへ正規化し、保存時にDocument.LineEndingへ変換する。

### 4.2 DocumentTabViewModel

Documentの状態をUIへ公開する。

```text
Document
DisplayTitle
IsModified
IsReadOnly
IsLoading
IsSaving
IsEditable

SearchText
IsRegex
SearchResults
CurrentSearchIndex
ReplaceNextStartIndex
```

`IsEditable` は以下で決定する。

```text
!IsReadOnly && !IsLoading && !IsSaving
```

Document自体に `INotifyPropertyChanged` を実装しない。

UI通知はViewModel側で行う。

---

## 5. ViewModel実装規約

ViewModelはCommunityToolkit.Mvvmの `ObservableObject` を使用する。

コレクションには `ObservableCollection<T>` を使用する。

コマンドには `RelayCommand` を使用する。

MVPでは `AsyncRelayCommand` を使用しない。

ViewModelは以下を直接実行してはならない。

* ファイルI/O
* Encoding処理
* 改行コード変換
* DiffPlex処理
* Regexによる検索・置換処理
* MessageBox表示
* AvalonEditの検索ロジック

これらは対応するUseCase、Application Service、Infrastructure、Presentation Behaviorへ分離する。

---

## 6. Command実装規約

MainWindowViewModelは以下のコマンドを提供する。

```text
New
Open
Save
SaveAs
Close
Exit

Search
Replace

Compare

FindNext
FindPrevious
ReplaceNext
ReplaceAll

NextDiff
PreviousDiff
```

Viewは原則としてMainWindowViewModelのCommandを呼び出すだけとする。

### 6.1 CanExecute

主な条件は以下とする。

| Command           | CanExecute                               |
| ----------------- | ---------------------------------------- |
| New               | `!IsProcessing`                          |
| Open              | `!IsProcessing`                          |
| Save              | Documentあり、ReadOnlyでない、Loading/Savingでない |
| SaveAs            | Documentあり、Loading/Savingでない             |
| Close             | ActiveTabあり、`!IsProcessing`              |
| Exit              | `!IsProcessing`                          |
| Find/Replace      | Documentあり                               |
| FindNext/Previous | Documentあり、検索結果あり                        |
| Compare           | `!IsProcessing`                          |
| Next/PreviousDiff | DiffTabかつ差分あり                            |

Command状態が変化した場合は `NotifyCanExecuteChanged()` を呼び出す。

---

## 7. Workspace・Tabの統合規約

Workspaceは以下を保持する。

```text
ObservableCollection<TabViewModel> Tabs
TabViewModel? ActiveTab
```

Tab追加時：

```text
Tabs.Add(tab)
ActiveTab = tab
```

TabControlは以下のBindingとする。

```text
ItemsSource  ←→ Workspace.Tabs
SelectedItem ←→ Workspace.ActiveTab
```

SelectedItemはTwoWay Bindingとする。

Documentを開く場合、同一ファイルが既にDocumentとして開かれていれば新しいTabを作成せず、そのTabをActiveTabにする。

ファイルパスは絶対パスへ正規化し、比較には `StringComparison.OrdinalIgnoreCase` を使用する。

---

## 8. ファイル処理の統合フロー

### 8.1 Open

```text
OpenCommand
 ↓
OpenDocumentUseCase
 ↓
IFileDialogService
 ↓
IFileService.ReadAllBytes
 ↓
IEncodingService.Decode
 ↓
ILineEndingService.Detect / NormalizeToLf
 ↓
Document生成
 ↓
DocumentTabViewModel生成
 ↓
Workspaceへ追加
```

読み込みが完了するまでDocumentをWorkspaceへ追加しない。

読み込み失敗時はTabを生成しない。

### 8.2 Save

```text
SaveCommand
 ↓
SaveDocumentUseCase
 ↓
Document.CurrentContent
 ↓
LineEnding変換
 ↓
Encoding
 ↓
IFileService.WriteAllBytes
 ↓
IsModified = false
```

保存失敗時は `IsModified=true` を維持する。

### 8.3 Save As

Save As成功後に以下を更新する。

```text
Document.FilePath
Document.FileName
Document.IsReadOnly = false
Document.IsModified = false
```

Save As先が別のDocumentで開かれている場合は拒否する。

---

## 9. Search / Replace統合規約

検索処理は `ISearchService`、置換処理は `IReplaceService` に分離する。

SearchServiceおよびReplaceServiceはAvalonEditを参照しない。

検索状態はDocument単位でDocumentTabViewModelに保持する。

編集が発生した場合：

```text
SearchResults = empty
CurrentSearchIndex = -1
```

とし、表示中の検索ハイライトも消去する。

検索条件自体は保持する。

正規表現検索では `.NET Regex` と `RegexOptions.Multiline` を使用する。

不正な正規表現の場合、Documentを変更せず、通知して検索結果を空にする。

Replace Nextでは1件のみ置換し、置換成功後は次回開始位置を更新する。

Replace AllはDocument全体を対象とし、`ReplaceNextStartIndex`には依存しない。

置換後に自動再検索は行わない。

---

## 10. Diff統合規約

Compareは保存済みファイルをディスクから読み込んで比較する。

未保存のDocument内容は比較対象としない。

```text
CompareCommand
 ↓
CompareDocumentsUseCase
 ↓
ファイル選択
 ↓
FileService
 ↓
EncodingService
 ↓
LineEnding Normalize
 ↓
DiffService
 ↓
DiffSession
 ↓
DiffTabViewModel
 ↓
Workspace
```

DiffPlexの具体型は `IDiffEngineAdapter` の内部、およびDiff表示Viewに限定する。

Application層のDiffモデルはDiffPlexに依存しない。

DiffTabは比較開始時点のスナップショットを保持する。

元ファイルが後から変更されても既存DiffTabは更新しない。

差分の単位は `DiffLine` とする。

`DiffCount` は `Unchanged` 以外のDiffLine数とする。

`CurrentDiffIndex` は0始まりとし、UI表示時のみ `+1` する。

Diff移動は循環しない。

---

## 11. AvalonEdit統合規約

AvalonEditはPresentation層に限定する。

DocumentとAvalonEditの同期は `TextEditorDocumentBehavior` が担当する。

### 初期表示

```text
Document.CurrentContent
        ↓
TextEditor.Text
```

初期同期やプログラムによる同期では、TextChangedイベントによってModified扱いにならないよう抑制フラグを使用する。

### ユーザー編集

```text
TextEditor.TextChanged
 ↓
Document.UpdateContent
 ↓
DocumentTabViewModel状態更新
 ↓
IsModified = true
 ↓
SearchResultsクリア
```

VMからEditorへの継続的な全量同期は行わない。

`EditorStateBehavior` は `DocumentTabViewModel.IsEditable` を `TextEditor.IsReadOnly` に反映する。

Caret位置、SelectionはPresentation側の状態とする。

---

## 12. StatusBar統合規約

Document表示例：

```text
UTF-8 | CRLF | Ln 10, Col 25
```

必要に応じて以下を追加表示する。

```text
変更あり
読み取り専用
読み込み中
保存中
```

行番号・列番号はAvalonEditから取得し、UI上は1始まりで表示する。

Diff表示例：

```text
比較: A.txt (UTF-8) ↔ B.txt (Shift-JIS) | 差分 3 / 10
```

比較処理中：

```text
A.txt ↔ B.txt | 比較中...
```

現在の差分が未選択の場合：

```text
差分 10件
```

または

```text
- / 10
```

とする。

## 13. エラー処理規約

Infrastructureで発生した低レベル例外を、そのままUIへ渡さない。

代表的なApplication例外：

```text
FileOperationException
EncodingOperationException
DiffOperationException
```

基本フロー：

```text
Infrastructure
 ↓
Application Exception
 ↓
MainWindowViewModel
 ↓
IUserNotificationService
 ↓
MessageBox
```

Application層からWPFのMessageBoxを直接呼び出してはならない。

代表的なメッセージ：

```text
ファイルを開けませんでした。
ファイルへのアクセスが拒否されました。
ファイルを保存できませんでした。
読み取り専用ファイルのため保存できません。
対応していない文字コードのため、ファイルを開けません。
現在の文字コードでは保存できない文字が含まれています。
```

MVPではリトライUIや詳細な例外情報表示は実装しない。

---

## 14. Close / Exit統合規約

変更ありDocumentを閉じる場合は、保存確認を行う。

結果：

```text
Save
DontSave
Cancel
```

Saveの場合、保存成功後のみTabを閉じる。

保存失敗またはSave Asキャンセルの場合はTabを閉じない。

Exitでは未保存Documentを処理し、保存が必要なDocumentの保存に失敗した場合は終了をキャンセルする。

終了処理の最終的なWindow終了操作はPresentation層で行う。

UseCaseから `Application.Shutdown()` を直接呼び出さない。

## 15. テスト実装規約

TestsプロジェクトではApplication層を中心にテストする。

Infrastructureは実ファイルを利用したI/Oテストを必要に応じて行う。

特に優先するテスト：

### Document

* 新規Documentの初期値
* 改行コード状態
* Modified状態
* ReadOnly状態
* Editable状態

### Encoding / LineEnding

* UTF-8
* UTF-8 BOM
* Shift-JIS
* BOM判定
* UTF-8優先判定
* 改行コード検出
* LFへの正規化
* 保存時の改行変換

### Search / Replace

* 通常検索
* 正規表現検索
* 不正Regex
* 0件
* 複数件
* 行境界
* ゼロ幅マッチ
* Replace Next
* Replace All
* キャプチャを利用した置換

### Diff

* 同一内容
* 追加
* 削除
* 変更
* 複数差分
* 差分数
* ナビゲーション境界
* 同一ファイル比較
* スナップショット保持

### UseCase

* Open成功/失敗
* Save成功/失敗
* Save As
* Close時のSave/DontSave/Cancel
* Exit時の保存
* Compare成功/失敗

## 16. 実装順序

実装は依存関係を考慮し、以下の順序を推奨する。

1. Domainモデル・Enum
2. Application Interface
3. Application Service
4. Infrastructure実装
5. UseCase
6. ViewModel
7. Presentation Service
8. AvalonEdit Behavior
9. View
10. Composition Root
11. テスト
12. 全機能の統合確認

まずDomain/Applicationのテスト可能な部分を完成させ、その後Presentationへ接続する。

---

## 17. 実装禁止事項

以下はMVPでは実装しない。

* DIコンテナ
* AsyncRelayCommand
* 非同期処理を前提とした設計
* 外部ファイル変更監視
* 検索の大文字・小文字切替
* 選択範囲のみの検索
* 置換後の自動再検索
* DiffTabのリアルタイム更新
* Diff結果の永続化
* Diffキャッシュ
* 高度なバイナリ判定
* Undo/RedoによるModified状態の再計算
* Application層からのWPF直接操作

MVPの設計範囲を超える機能を、実装上の都合で追加しない。

## 18. 最終統合チェックリスト

実装完了時、最低限以下を確認する。

* [ ] 起動時に「無題1」が1つ作成される
* [ ] 無題番号はアプリ起動中に再利用されない
* [ ] 同一ファイルを二重にDocumentとして開かない
* [ ] FilePathは絶対パスで保持する
* [ ] Document内部改行はLF
* [ ] 保存時にDocument.LineEndingへ変換する
* [ ] UTF-8 / UTF-8 BOM / Shift-JISを扱える
* [ ] 保存できない文字でModified状態を失わない
* [ ] ReadOnly Documentは通常編集・Saveできない
* [ ] Save AsはReadOnly Documentでも実行できる
* [ ] 検索状態はDocumentごとに保持される
* [ ] 編集時に検索結果を無効化する
* [ ] 不正RegexでDocumentを変更しない
* [ ] Replace Nextが開始位置を正しく更新する
* [ ] Replace Allが全体を対象とする
* [ ] Compareはディスク上の保存済みファイルを比較する
* [ ] Compare失敗時にDiffTabを作成しない
* [ ] DiffTabは比較時点のスナップショットである
* [ ] DiffCountは差分行グループ数である
* [ ] Diff移動は循環しない
* [ ] ViewがApplication/Infrastructure処理を直接実行しない
* [ ] ApplicationがWPF/AvalonEdit/DiffPlex.Wpfへ依存しない
* [ ] File I/OがViewModelに存在しない
* [ ] MessageBox呼び出しがApplication/Domainに存在しない
* [ ] Close時の保存失敗でTabを閉じない
* [ ] Exit時の保存失敗で終了しない
* [ ] CommandのCanExecuteが状態変化に追従する

## 19. 詳細設計全体の実装原則

TextWorkbenchの実装では、以下を最終原則とする。

1. **DocumentはUIから独立したデータモデルとする。**
2. **ViewModelはUI状態とCommandを管理し、具体的なI/O処理を持たない。**
3. **ApplicationはUseCaseと業務ロジックを担当する。**
4. **Infrastructureは外部システムとの接続を担当する。**
5. **AvalonEditはPresentationに閉じ込める。**
6. **DiffPlexの具体型はAdapterとViewに閉じ込める。**
7. **検索・置換ロジックはAvalonEditから分離する。**
8. **ファイルの文字コードと改行コードを明示的に管理する。**
9. **失敗時には状態を不正に確定させない。**
10. **MVPで定義していない機能を勝手に追加しない。**

この原則を維持することで、各機能を個別に実装しても、Workspace、Document、検索・置換、Diff、ファイルI/O、UIが相互に密結合することを防ぐ。
